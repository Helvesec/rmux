# tmux Compatibility Decisions

This document explains the human-readable tmux compatibility policy in RMUX.
The structured source of truth for accepted product divergences is
`tests/reference/tmux_compat/divergences.toml`. A compatibility claim is
accepted only after a current head-to-head probe against tmux and the current
RMUX tree.

The divergence matrix and its machine-readable report are generated directly
from that ledger:

```sh
cargo xtask registry-docs --output-dir docs/generated
cargo xtask registry-docs --output-dir docs/generated --check
```

`compliance.md` and `compliance.json` retain every registered evidence reference,
limitation and deferral. Generation checks declarations; it does not execute
that evidence or issue a compatibility verdict. The same command also emits
`cli-reference.md`, `configuration-reference.md` and `rmux.1` from the implemented
CLI and configuration registries. Platform defaults are labelled explicitly;
the same generated bytes can be checked on Linux, macOS and Windows.
The generated `rmux.1` is also the installed manual in `docs/man/rmux.1`;
the default `docs/generated` destination checks both copies. Use another
`--output-dir` for an isolated projection without changing the installed manual.
Run these commands from the repository root. The checker reads the current
divergence ledger and validates its policy, IDs and current source references
before comparing every artifact byte for byte. A retired entry declares
`retired_by` (its decision ID), keeps `inventory = "none"` and retains source
regression `tests`. Its `historical_evidence` preserves commit locators and
relative archive locators as declared provenance: their syntax is checked, but
their availability and contents are not verified. Ordinary `evidence` and `tests`
still require current files and any named test symbols, including for retired
entries. Neither command executes that evidence.

## CI Policy

New compatibility fixes should land with focused Rust tests or POSIX shell
head-to-head probes. Avoid adding Python infrastructure for the generated matrix.

Known gaps are allowed to remain documented while they are intentionally
out-of-scope for a release, but a compatibility requirement must have a
failing Rust/shell regression test when work starts on that behavior.

## OSC 7501 program status

Measured against tmux 3.7b: a pane that writes `OSC 7501 ; ? ST` (or BEL)
followed by a primary DA receives only `ESC [ ? 1 ; 2 c`, and tmux keeps no
record of OSC 7501 reports. RMUX deliberately diverges: the pane parser answers
the query itself, with the matching terminator and before the DA reply, and
stores bounded reports exposed through the `*program_status*` formats (see
[Program status](program-status.md)). Writers that do not store reports stay
silent, as tmux does. Regression coverage:
`crates/rmux-core/src/input/tests/osc_dcs_misc.rs::osc_7501_query_is_answered_by_the_pane_screen_before_primary_da`
and `osc_7501_query_is_silent_for_writers_without_program_status`.
