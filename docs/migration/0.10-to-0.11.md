# Migrating RMUX 0.10 → 0.11

For the exact build and its qualification results, see the
[candidate reference](../release/0.11.0.md#candidate-reference).

0.10.0 (wire 8) and 0.11.0 (wire 9) have no overlapping wire compatibility.
You must restart the daemon: installing or replacing the client does not
convert an existing daemon. **Open sessions are lost when it stops.** You
cannot carry running processes, live editor state or application memory into
the new daemon by attaching again. Detaching only leaves the old daemon alive.

Schedule an interruption and use the steps below in order. Apply them to every
daemon endpoint, including endpoints owned by another user or running on a
remote host. Coordinate with other attached users before stopping a shared
daemon. Windows 10 is not qualified; this procedure makes no Windows 10 claim.

The commands below are examples, not an automatic migration script. Replace
the executable paths, session/pane targets and directories with your own.
`-L work` selects an example named endpoint; omit it for the default endpoint
or consistently replace it with `-S /your/socket/path` for an explicit socket.
Never change the selector between saving, stopping and recreating that daemon.
On Windows, retain the same selector for the corresponding named-pipe endpoint.

## 1. Save application work and a recovery record

Before changing the installation, retain the complete verified 0.10.0
distribution in a separate directory, including helpers, daemon and dependencies.
Keep an installer/package version usable for rollback. A copied public CLI alone
may not work. Use that old client to inspect the wire-8 daemon; a new wire-9
client cannot be relied on to read its sessions.

Save files from editors and application-native checkpoints from jobs or
databases, then finish or stop those applications normally. Record full commands,
arguments and working directories needed to start them again. The process name
shown by `list-panes` is not a complete command line or an application checkpoint.

Create a fresh private backup directory for each endpoint every time you save.
Record the directory path with the host, account and endpoint selector so you
can find the right inventory when recreating sessions. Use the same directory
for that endpoint's configuration, included files, plugin settings and any
intentional environment/startup settings. Keep the original configuration intact
for rollback. A configuration backup alone cannot recover a session. Protect
saved files and terminal output because scrollback may contain secrets.

For example, on macOS/Linux, using the retained distribution:

```sh
RMUX010=/path/to/retained-0.10.0/bin/rmux
(
    set -e
    umask 077
    backup_dir=$(mktemp -d "$HOME/rmux-upgrade-backup.XXXXXXXX")
    printf 'Recovery directory: %s\n' "$backup_dir"
    "$RMUX010" -L work list-sessions > "$backup_dir/sessions.txt"
    "$RMUX010" -L work list-windows -a > "$backup_dir/windows.txt"
    "$RMUX010" -L work list-panes -a -F '#{session_name}:#{window_index}.#{pane_index} #{pane_current_path} #{pane_current_command}' > "$backup_dir/panes.txt"
    "$RMUX010" -L work capture-pane -p -S - -t work:0.0 > "$backup_dir/work-0-0.txt"
)
```

Capture every pane whose output you need, with a separate file and its actual
target from `panes.txt`; the last command captures only one example pane.
Add those capture commands inside the subshell so the same private directory
and file permissions apply.
It saves retained textual scrollback and the normal screen, not output already
discarded by the history limit, an alternate-screen application's full state,
images or pending input. A capture is not a process checkpoint. Open and inspect
each saved file, and check each command's exit status before proceeding. If any
backup command fails, stop here and resolve it using the matching old client.

On Windows 11, use PowerShell with the retained archive layout. The archive's
public client is `rmux.exe` at its root, beside `rmux-daemon.exe`; `bin\rmux.exe`
is an installed-prefix path, not the archive path. Keep `libexec` and the other
archive contents in place. Use a profile directory whose inherited permissions
keep the backup private, or select another parent with private permissions.

```powershell
$rmux010 = 'C:\tools\retained-0.10.0\rmux.exe'
$backupDir = Join-Path $env:USERPROFILE ("rmux-upgrade-backup-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $backupDir -ErrorAction Stop | Out-Null
Write-Output "Recovery directory: $backupDir"
& $rmux010 -L work list-sessions | Set-Content -Encoding utf8 -ErrorAction Stop -LiteralPath (Join-Path $backupDir 'sessions.txt')
if ($LASTEXITCODE -ne 0) { throw 'list-sessions failed; do not continue' }
& $rmux010 -L work list-windows -a | Set-Content -Encoding utf8 -ErrorAction Stop -LiteralPath (Join-Path $backupDir 'windows.txt')
if ($LASTEXITCODE -ne 0) { throw 'list-windows failed; do not continue' }
& $rmux010 -L work list-panes -a -F '#{session_name}:#{window_index}.#{pane_index} #{pane_current_path} #{pane_current_command}' | Set-Content -Encoding utf8 -ErrorAction Stop -LiteralPath (Join-Path $backupDir 'panes.txt')
if ($LASTEXITCODE -ne 0) { throw 'list-panes failed; do not continue' }
& $rmux010 -L work capture-pane -p -S - -t work:0.0 | Set-Content -Encoding utf8 -ErrorAction Stop -LiteralPath (Join-Path $backupDir 'work-0-0.txt')
if ($LASTEXITCODE -ne 0) { throw 'capture-pane failed; do not continue' }
```

PowerShell captures are text recovery notes, not byte-for-byte process images.
Check file-write errors as well as the native exit code, and inspect the files.
Repeat the pane capture with real targets, and copy configuration separately.

Neither resurrect nor continuum is a guaranteed recovery path for this upgrade.
An existing plugin save may be retained as supplementary information, but its
compatibility and restore behavior are not guaranteed. Window/layout snapshots
also do not restore running processes or replace application-native saves.

## 2. Stop the old daemon deliberately

After verifying the saves and getting other attached users ready, stop the
selected daemon with the matching old binary:

```sh
"$RMUX010" -L work kill-server
```

On Windows 11:

```powershell
& $rmux010 -L work kill-server
if ($LASTEXITCODE -ne 0) { throw 'daemon stop failed; investigate before installing' }
```

This ends all sessions on that endpoint and disconnects their clients. Treat
pane processes as terminated or unrecoverable; do not assume that background
children survive or are safely completed. Confirm successful shutdown before
installing or starting the new daemon. Stop other old endpoints separately with
their own selectors. Do not delete an active socket/pipe as an upgrade method.

If you already installed 0.11 and see “uses incompatible protocol 8”, do not
retry ordinary attach/save commands against the old daemon. Use the retained
0.10.0 client for the saves above first. The current
[shutdown path](../../src/cli/server_commands.rs) also has a legacy-wire
`kill-server` fallback, but it still destroys the old sessions and is not
a backup or restoration facility.

## 3. Install and verify the matching 0.11 client and daemon

Use the final release's verified archive or your existing package manager once
that channel actually provides 0.11. Keep the archive's complete layout and run
its included `install.sh` or `install.ps1` as applicable. Do not overlay just
one executable or mix retained 0.10 helpers with the new installation. Avoid
installing from multiple channels into the same prefix.

Verify the release's checksums/signature/provenance as described in
[SECURITY.md](../../SECURITY.md). Check the executable resolved by `command -v
rmux` on macOS/Linux or `Get-Command rmux` on Windows, then run `rmux -V`;
the selected release client must report 0.11.0 (or the exact intended RC version).
The local 0.11.0 source version does not certify a released 0.11 binary.

macOS binaries use ad hoc signatures and are not notarized; Windows RMUX
binaries are unsigned, without RMUX Authenticode. See the
[release notes](../release/0.11.0.md#downloads-channels-and-signatures) for trust
prompts and channel availability. Do not assume WinGet or another pending
channel already carries this release.

## 4. Recreate sessions and restart applications

Start a new session using the new client and the intended endpoint. For example,
after installing and resolving the correct `rmux`:

```sh
rmux -L work new-session -d -s work -c /path/to/project
rmux -L work list-sessions
rmux -L work attach-session -t work
```

In PowerShell, use the same RMUX commands with a Windows working directory,
such as `rmux -L work new-session -d -s work -c 'C:\path\to\project'`.
Check success at each step. Recreate any additional windows and panes from your
saved recovery record, then restart applications with their own saved files or
checkpoints. Read the captured output as a reference; do not automatically
execute terminal text or load it as if it restored a running session.

Retain the backup until you have checked application data and normal workflows.
If an incompatibility diagnostic remains, check the resolved client, helper
layout and selected endpoint before stopping anything else; you may have reached
another old daemon. No live-session continuity is promised by this procedure.

## Roll back

Rollback restores an installation, not the sessions lost during either stop.
Save new application work and recovery notes first, using the matching 0.11
client. Stop the 0.11 daemon with that client on each affected endpoint:
`rmux -L work kill-server`. Check success before changing the installation.

Reinstall the complete retained 0.10.0 package through the same installation
channel, restore the pre-upgrade configuration copy if needed, and verify that
the resolved client reports 0.10.0. A wire-8 client cannot operate a still-running
wire-9 daemon. Create fresh sessions with the 0.10 client and restart applications
from their own saved data. Configuration or plugin state written by 0.11 may not
be backward compatible; do not overwrite the original backup to force a restore.

If the old installer or channel cannot provide 0.10.0, resolve package recovery
before removing the working installation. Uninstallation by itself recovers no
sessions. The [deferred scope](../release/0.11.0.md#deferred-scope) describes the
remaining persistence, platform and SDK limitations.
